# Repository structure

**This is a specification, not a description.** Most of the directories below do not
exist yet. Each milestone creates the parts it needs, in the shape defined here, so that
placement is never re-decided mid-task.

Rule: **if you are adding a file and this document does not say where it goes, say so and
propose an addition here before writing it.** Do not invent a parallel convention.

---

## Top level

```
GGallery/
  .claude/          permission rules and the git guard hook
  docs/             specifications — this file, DESIGN, DATA-MODEL, ENGINEERING-NOTES
  src/              frontend — React + TypeScript
  src-tauri/        backend — Rust
  tools/            sidecar binaries, fetched on first run, gitignored
  index.html        Vite entry point
  package.json      frontend dependencies and scripts
  tsconfig.json     TypeScript configuration
  vite.config.ts    dev server, Tailwind plugin, worker format
  CLAUDE.md         instructions for Claude Code
  PLAN.md           roadmap, locked decisions, non-goals
  README.md         install and usage
  gallery.config.json   machine-local, gitignored — path to the library root
```

`src/` and `src-tauri/` are generated by the Tauri scaffolder at the start of M1. Do not
hand-create them beforehand.

Inside `src-tauri/`, alongside `src/`: `Cargo.toml`, `build.rs`, `tauri.conf.json`,
`capabilities/` (per-window permission grants) and `icons/` (the `.ico` `tauri-build`
embeds as a Windows resource).

### Boundaries that matter

**`commands/` is a thin shell.** Every command is `async fn`, wraps real work in
`tauri::async_runtime::spawn_blocking`, and contains no business logic — it validates
input, calls into `db/`, `media/` or `jobs/`, and maps errors. A synchronous command
freezes the native window message pump; see
[ENGINEERING-NOTES.md](ENGINEERING-NOTES.md).

**`fs/paths.rs` is the only place that converts between absolute and library-relative
paths.** Every read and write of a path goes through it. This is the single chokepoint
enforcing "no absolute paths in the database" — the rule the whole portability promise
rests on. If path handling appears anywhere else, that is a bug regardless of whether it
currently works.

**`db/` owns SQL.** No query strings outside it. Commands call functions, not queries.

**`sidecar/` owns process spawning.** Nothing else shells out to ffmpeg, HandBrake,
yt-dlp or gallery-dl.

**The job queue's SQL lives in `db/jobs.rs`, its runner in `jobs/`.** The split follows
the rule above rather than bending it: `jobs/` decides what to run and when, `db/jobs.rs`
is the only file that writes the `job` table.

## Frontend — `src/`

```
main.tsx
App.tsx

lib/
  ipc.ts              typed wrappers over invoke() — no raw invoke calls elsewhere
  types.ts            shared types, mirroring the Rust structs
  query.ts            query-string parsing and manipulation for the search bar
  format.ts           sizes, durations, dates — one implementation, used everywhere

state/
  library.ts          current root, index status
  selection.ts        selected items, last anchor for shift-click
  ui.ts               panel visibility, thumbnail size, sort, blur toggle

features/             one folder per surface in DESIGN.md
  grid/               PORT FROM THE M0 SPIKE — architecture already validated
    Grid.tsx
    Tile.tsx
    Scrubber.tsx
    useJustifiedLayout.ts
    layoutWorker.ts
  sidebar/
  indexing/           index progress readout and the per-file failure list
  import/             M1.7 — the startup flow's full-window Review and Progress
                      screens (Choose folder is the picker itself, in App.tsx),
                      plus the Settings → Normalise filenames repair modal that
                      reuses the same one-screen-review shape against an
                      already-open library
  settings/           M1.6 — deliberately minimal, just Normalise filenames for now;
                      the real Settings screen is M9's job
  folder/             folder header, archetype fields, status
  preview/            the resizable right panel — preview, details, tags
  search/
  theatre/            in-app large view; multi-view lands here in M10
  triage/             M4
  downloads/          M5
  review/             M6 — compression comparison
  duplicates/         M7
  storage/            M8

components/           shared primitives only — button, dialog, chip, tooltip
styles/
```

### Boundaries that matter

**A `features/` folder owns its surface completely** — components, hooks and local state
together. Cross-feature imports go through `lib/` or `state/`, never by reaching into
another feature's internals.

**`components/` is for primitives with no domain knowledge.** If it knows what an item or
a folder is, it belongs to a feature.

**`grid/Tile.tsx` exports a DOM pool, not a component**, despite the `.tsx` name. Tiles
are recycled nodes because mount/unmount churn fails the fling target — see
[ENGINEERING-NOTES.md](ENGINEERING-NOTES.md) §1. The filename is kept so the grid's
files stay where this document says they are.

**`lib/ipc.ts` is the only file that calls `invoke()`.** Everything else calls typed
functions, so a backend signature change breaks at compile time in one place.

## Naming

- Rust files and modules: `snake_case`. React components: `PascalCase.tsx`. Hooks:
  `useThing.ts`. Everything else in `src/`: `camelCase.ts`.
- Migrations: `NNN_short_description.sql`, zero-padded, never edited after shipping.
- No `utils.rs`, `helpers.ts`, `common/` or `misc/`. If a home is not obvious, the module
  boundary is wrong — fix that rather than adding a drawer.
